## 1. Business Purpose
Nexus is a comprehensive, AI-first "operating system" designed to bridge the gap between isolated AI tools and a unified, memory-enabled platform for personal and professional automation. 

**Core Objectives:**
- **Contact Management & Intelligence:** A CRM engine (Contacts Hub) enriched with AI that extracts preferences, memories, and emotional baselines from conversations.
- **Cognitive Core (Hedra Soul / Souly):** An AI assistant that goes beyond chat by utilizing versioned memories, context snapshots, and explicit user approval requests before taking autonomous actions.
- **Multi-Agent Orchestration:** A framework to deploy specialized AI workers (Agents Hub) that handle discrete tasks (e.g., Contact Analysis, Memory Maintenance) using MCP tools and custom personas.
- **Proactive Automation:** Workflows and Event-Condition-Action (ECA) rules that allow the system to trigger actions (like WhatsApp messages via WAHA) on schedules or events.
- **Dynamic AI Routing:** An AI Models Hub that abstracts LLM providers (OpenAI, Anthropic, Gemini, local), allowing dynamic switching, cost tracking, and budget management without code changes.

## 2. Tech Stack & Architecture Pattern

**Tech Stack:**
- **Framework:** Laravel 13 (PHP 8.3+)
- **Architecture:** Monolithic (Backend + Frontend served from the same codebase)
- **Frontend:** Blade Templates, Vanilla CSS, TailwindCSS, Vite
- **Database:** MySQL / PostgreSQL
- **Caching & Queues:** Redis, Laravel Horizon
- **WebSockets:** Laravel Reverb (Real-time events & broadcasting)
- **Authentication:** Laravel Sanctum
- **Dev Tools:** Telescope, Clockwork, Debugbar, Pail, Pint
- **Testing:** PHPUnit 11

**Architecture Pattern: Domain-Driven Hubs**
The application is strictly modularized into 15+ "Hubs" (e.g., Contacts, Agents, AI Models, Workflows, Tasks, Settings). 
- **Decoupled Domains:** Each Hub encapsulates its own Controllers, Services, and Models.
- **Boundary Enforcement:** Cross-hub database writes are prohibited; Hubs must communicate via Service contracts or Laravel Events.
- **Asynchronous-First:** Any task requiring significant time (AI inference, contact analysis, memory maintenance, sending notifications) is dispatched to a Redis queue via Laravel Horizon.

## 3. Core Entities & Database Flow

The database consists of 74+ migrations with heavily relational structures.

**Core Entities:**
- **User:** The operator and owner of the ecosystem.
- **Contact:** The central CRM entity, heavily extended by sub-models (`ContactIdentifier`, `ContactMemory`, `ContactMessage`, `ContactPreference`).
- **Agent & AgentTask:** AI definitions (type, persona, MCP tools) and their execution instances.
- **Workflow & WorkflowExecution:** Automation templates (steps, triggers) and their runtime logs.
- **HedrasoulSession & HedrasoulMessage:** The AI conversational state. Includes `SoulyActionTrace` for reasoning steps and `HedrasoulContextSnapshot` for point-in-time context.
- **Memory:** Structured and graph-based facts extracted from conversations with confidence scores and decay logic.
- **AIProvider, AIApiKey, AIModel:** The dynamic LLM registry for routing and executing AI requests securely.
- **EcaRule & ProactiveTrigger:** Natural language rules converted into temporal/event-based executions.
- **Log:** Dual-write application audit trail (file + database).

**Standard Data Flow:**
1. **Trigger:** Web UI (Blade) or API Client hits a route (`web.php` or `api.php`).
2. **Controller:** Validates the request using a Form Request.
3. **Service:** Executes business logic. If the task is heavy (e.g., contacting an LLM via `AIModelsHub`), the Service dispatches a Job.
4. **Queue (Horizon):** Background worker picks up the Job, executes the external API call, and updates the Database.
5. **Real-Time Update (Reverb):** The Job broadcasts a WebSocket event to the frontend (e.g., updating the task status or rendering an AI response).

## 4. Coding Standards & Conventions

- **Thin Controllers, Fat Services:** Controllers are exclusively for HTTP routing, validation, and JSON API Resource transformation. All business logic must reside in Service classes.
- **Strict Eloquent Rules:** 
  - Always explicitly define `$fillable` (never use `$guarded = []`).
  - Always cast attributes (`$casts`).
  - No raw SQL queries; use Eloquent scopes.
- **Error Handling:** Services must use `try-catch` blocks. Exceptions should never bubble up to the HTTP layer. Errors must be logged with structured context.
- **PHP 8.3+ Features:** Mandatory use of constructor property promotion, strict typing on all parameters and returns, and match expressions.
- **Testing & Formatting:** PHPUnit is the standard (no Pest). Laravel Pint (`--dirty --format agent`) must be used before finalizing code.
- **API Design:** All APIs are versioned under `/api/v1/`, authenticated via Sanctum, and exclusively return JSON.

## 5. Potential Technical Debt & Critical Areas

Based on the architectural review, the following areas require strict attention:

1. **Queue Dependency (Single Point of Failure):** 
   Since Nexus is asynchronous-first, the entire "cognitive" functionality (AI inference, memory updates, workflow execution) is dependent on Redis and Laravel Horizon. If the queue backs up or fails, the platform loses its AI capabilities. Strict DLQ (Dead Letter Queue) monitoring is essential.
   
2. **Cross-Hub Data Integrity:** 
   With 15+ Hubs and a rule against direct cross-hub database writes, maintaining boundary discipline is difficult. We must ensure that rapid feature development doesn't result in "leaky abstractions" where one Hub tightly couples to another Hub's Eloquent models.

3. **Database Growth & Dual-Write Logging:**
   The `logs` table and AI trace tables (`souly_action_traces`, `hedrasoul_context_snapshots`) will grow exponentially as agents run autonomously. Aggressive pruning and archiving strategies (Log pruning) must be enforced to prevent database bloat.

4. **AI Failover Mechanisms:**
   The documentation notes that "Fallback provider chains" are only partially implemented. Given the unreliability of external LLM APIs, completing this feature is critical so the system can gracefully degrade to secondary providers (e.g., OpenAI -> Anthropic -> Local) without interrupting autonomous agents.

5. **Monolithic Transition Artifacts:**
   The project recently migrated from a Next.js frontend to Blade templates. We must watch out for residual REST endpoints being used sub-optimally by Blade views instead of direct Service calls, which could introduce unnecessary HTTP overhead within the monolith.
