Core Architectural Layers

1. Contact Unification & Multi-channel Inbox

The Contacts Hub resolves inbound webhooks or data uploads from WhatsApp and Facebook Messenger to a single Contact ID. When an inbound message is received via `ProcessWahaWebhookJob` or Facebook pipelines:

  • The system checks the `contact_identifiers` table using normalized identifiers (phones stripped to numeric values, emails lowercased).
  • If a match is found, the message is linked to that profile.
  • If a match is not found, the `ContactMessageNormalizer` performs name similarity matching using Levenshtein distance computations in memory. If similarity is less than 80%, a new individual contact profile is created dynamically.

2. Asynchronous AI Intelligence Extraction

Triggered via `POST /contacts/{id}/analysis-runs`, this layer executes NLP analysis to generate rich contact context:

  • Gathers up to 100 historical messages in reverse chronological order.
  • Submits payload instructions to the `UniversalAiGatewayService` using an AI model profiler.
  • Extracts key profiling categories: discussion topics, character persona summaries, emotional baselines, and recommended autopilot response guidance.
  • Saves results as `ContactAnalysisFinding` logs with evidence links and updates the contact's metadata for immediate AI reply contextualization.

3. GDPR Compliance, Auditing, and Transactional Rollbacks

Contains secure privacy protection features and batch management controls:

  • Erasure Pipeline: Dispatches `EraseContactDataJob` to securely clean MySQL records and calls `ContactPrivacyService` to wipe vectorized memory indexes from Pinecone.
  • Audit Logs: Registers all user operations (including identity conflicts and failed runs) into the `contact_audit_events` log database.
  • Transaction Rollback: `ContactImportRollbackService` runs a DB Transaction deleting imported message records and dispatching rollback broadcasts.

Contacts Hub Codebase Explorer

Inspect code architectures, variables, scopes, and inner logical steps of the core Contacts Hub PHP classes.

Responsible for taking message packages parsed by WAHA or Facebook and generating unified records in `contact_messages`.

Key Properties & Scopes
  • `private array $existingHashes`: Stores dedupe key indices.
  • `private array $resolvedContactsCache`: Cache of names for fast O(1) loop lookups.
Primary Methods
  • `normalizeAndCreate(parsedMsgs, contact, source)`: Main pipeline processor.
  • `resolveSenderContact(parsedMsg, mainContact)`: Resolves name/phone match.
  • `isSameContact(name1, name2)`: Computes Levenshtein similarity rating.
Inner Code Workflow:
  1. Fetches existing SHA-256 hashes of contact's messages: `array_flip(ContactMessage::pluck('dedupe_hash'))`
  2. Loops through inbound parsed arrays: Computes hash = `hash('sha256', timestamp | sender | body)`.
  3. If hash matches existing, skips message (per-contact duplicate protection).
  4. If direction is inbound, parses sender name. If Levenshtein distance similarity > 80% matches main contact, routes to contact record. Else, creates a new individual contact profile.
  5. Detects message language (matches Arabic regex range `\x{0600}-\x{06FF}` or Cyrillic, defaults to English).
  6. Inserts into `contact_messages` table and updates contact's `last_interaction_at`.

Parses dialogue logs to build context parameters and enrich contact metadata properties.

Key Dependencies
  • `UniversalAiGatewayService $aiGateway`
  • `LogService $logService`
Primary Methods
  • `process(ContactAnalysisRun $run)`: Main intelligence pipeline handler.
Inner Code Workflow:
  1. Queries the contact's historical messages, ordered by timestamp, limiting to 100 context items.
  2. Formats dialogue context string into: `[direction] body \n`.
  3. Formulates system and user LLM prompts instructing JSON extraction for topics, persona summaries, emotional baselines, and suggeted response rules.
  4. Submits payload to the gateway via LLM Profiler agent.
  5. Parses LLM response (removes markdown formatting and decodes JSON).
  6. Loops through topics, persona, and emotional baselines to create `ContactAnalysisFinding` records with source message IDs as evidence links.
  7. Directly updates contact's metadata JSON attributes for immediate profile enrichment.

Parses WhatsApp chat histories exported in TXT or JSON format.

Supported Formats
  • TXT exports (iOS and Android dialects).
  • JSON formats (raw message arrays).
Primary Methods
  • `parseTxt(content, phone, timezone)`
  • `parseJson(json, phone, timezone)`
  • `isSystemMessage(body)`
Inner Code Workflow:
  1. Explodes text payload by newline characters to loop through lines.
  2. Evaluates regex: `^\[(\d{4}-\d{2}-\d{2}),\s*(\d{2}:\d{2})\]\s+(.*?):\s+(.*)$` to match date, time, sender name, and message content.
  3. If matched, initiates new message object. Strips system entries like "messages and calls are encrypted" or call timestamps.
  4. If a line does not match the date prefix, appends the text to the active message as a multi-line continuation.
  5. Parses timestamps using Carbon and normalizes all records to UTC timezone.
