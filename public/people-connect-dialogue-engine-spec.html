مواصفات Dialogue Task Engine

الغرض

تحويل المحادثات إلى أهداف قابلة للتتبع والتحقق، مع متابعة لحظية وتقييم تلقائي للوصول للهدف.

النطاق

Outgoing Goal Chat + Incoming Goal Handler + Relationship Nurture Tasks.

الالتزام

Human-in-the-Loop: أي موضوع حساس أو غير مسجل يوقف التنفيذ فوراً ويصعد لهدرا.

المصادر

PeopleConnect Conversations + ContactStance + ContactReplyRule + WAHA events.

متطلبات النظام

  • هوية موحدة: كل شخص له ملف واحد حتى لو حسابات WhatsApp و Messenger متعددة.
  • حالة حوار حية: تتبع تلقائي لحالة المحادثة: initiated → in_progress → goal_satisfied → escalated/closed.
  • تقييم هدف ذكي: بعد كل رسالة يتم تقييم: هل الهدف تحقق؟ هل نحتاج مزيد نقاش؟ هل يجب التصعيد؟
  • Checkpoints: نقاط تفتيش داخل المحادثة لتسجيل التقدم والنتائج الجزئية.
  • تصعيد فوري: موضوع مادي/قرار مصيري/غير مسجل → إيقاف + تنبيه Telegram + Dashboard alert.
  • أداء: لا يكرس SQL queries زائدة؛ يستخدم Redis cache للـ context assemblies.

Workflow الكامل

/* Outgoing Goal Chat */ [Create Dialogue Task] → [Assemble Context] → [Build Hedra-Twin Prompt] → [Send via WAHA/Messenger] → [Receive Reply] → [Analyze + Update Facts/Stances] → [Evaluate Goal] → [Goal Met?] → Yes → [Close + Summary] / No → [Continue or Escalate] /* Incoming Message */ [Webhook Event] → [Resolve Contact] → [Fetch Active DialogueTask + Stances] → [Build Reply] → [Hedra Approval Gate?] → Approved → [Send] / Blocked → [Alert Hedra] → [Log Message + Update History + Evaluate Goal]

منطق تشغيل المحرك

/* Core Logic Rules */ 1. Context Assembly - Fetch Contact + Stances + Rules + RecentMessages + ActiveDialogueTask - Build prompt block: facts / stances / boundary_rules / hedra_twin_style / goal 2. Reply Generation - IF reply_mode_override == 'auto' AND no sensitive topic → send auto - IF reply_mode_override == 'draft' → save draft, notify Hedra - IF reply_mode_override == 'manual' → never send without explicit Hedra approval 3. Goal Evaluation (after every message) - Compare target_outcome vs last_message + conversation_thread - IF confidence >= 0.85 → mark goal_satisfied - IF sensitive topic OR unknown fact → escalate immediately 4. Memory Update - On every closed task: update contact.memory_freshness - On new stance change: insert ContactStance + audit log - On new fact: upsert ContactFact with confidence + source

قواعد الأمان والحدود

  • التصعيد الفوري: أي رسالة تحتوي على مال/قرار/طلاق/عمل/مشكلة قانونية → stop + Telegram alert.
  • عدم تجاوز القواعد: boundary_rules تُطبّق كـ hard stop قبل إرسال أي رد.
  • تسجيل كامل: كل رسالة + قرار + سبب تصعيد تُسجل في PeopleConnectProcessingLog.
  • فصل الأدوار: people-orchestrator يدير الأهداف، people-waha يدير الإرسال، people-persona يبني الاقتراح.

خطة التنفيذ المقترحة

Phase 1: Audit & Gap Analysis - مراجعة PeopleConnectConversation + DialogueTask + ContactStance الحالية - تحديد النواقص: هل goal evaluation service موجود؟ هل checkpoint_data يُستخدم؟ - المخرج: تقرير فراغات + قرار تعديل vs إضافة Phase 2: Logic & Rules Layer - كتابة PeopleConnectGoalEvaluationService - كتابة PeopleConnectEscalationPolicy - ربط ContactReplyRule بنظام التصعيد Phase 3: UI & Dashboard - لوحة مهام + محادثة مباشرة + أزرار تدخل يدوي - موصل بـ LiveMsgsSyncService + RealtimeBroadcaster Phase 4: Testing & Hedra Review - سيناريوهات اختبار: incoming/outgoing/sensitive topic - مراجعتك + تعديل + اعتماد نهائي
