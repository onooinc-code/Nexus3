⚠️ ملف تخطيط فقط (Planning-Only) — لم يُنفذ أي كود بعد. للمراجعة والاعتماد.

النظرة العامة للمشروع

🎯 الهدف: بناء بروفايل كامل لكل جهة اتصال في Nexus يجمع كل حرف عنها (هوية، حقائق، شخصية، مواقف هدرا، مواضيع، كل الرسائل، ملاحظات وتنبيهات، شبكة علاقات) — مع تخزين الرسائل بالكامل في RAGFlow (chunks + memories) — بحيث يتواصل الـ agent المسؤول بأفضل شكل ممكن.

المصادر (Inputs)

١. رسائل واتساب قديمة (WAHA/backup)
٢. رسائل فيسبوك قديمة (Messenger export)
٣. ملفات XML لبروفايل الفيسبوك

المخازن (Stores)

MySQL/Nexus (مهيكل) + RAGFlow (chunks+memories) + message_history_index (فهرس)

المخرجات (Outputs)

بروفايل كامل لكل contact + Agent Handoff Protocol + Visual Board + تنبيهات هدرا

📌 قاعدة التنفيذ: نبدأ بجهة اتصال تجريبية واحدة (موثوقة) + واحدة حساسة (مثل مارلين) لاختبار الـ boundary قبل التعميم على الكل.

Phase 0 — التحضير واكتشاف المصادر

الهدف: تحديد إيه المتاح فعلاً قبل كتابة أي كود.

الخطوات

1
جرد المصادر: هدرا يحدد إيه المتاح:
  • رسائل واتساب — من WAHA live API؟ ولا من backup/export ملف؟
  • رسائل فيسبوك — عندك Messenger export؟ (تنسيق JSON/HTML؟)
  • ملفات XML — عندك ملفات معينة لبروفايلات معينة؟
2
تأكيد RAGFlow: API key موجود ✅ — نحدد استراتيجية الـ datasets (Dataset لكل contact ولا Dataset واحد بـ metadata filtering). التوصية: Dataset لكل contact لعزل أفضل.
3
اختيار Pilots: contact واحد موثوق (مثلاً عميل/شريك) + contact واحد سام/مقطوع (مارلين) لاختبار الـ boundary_rules والـ trust_score.
4
تأكيد المخطط: مراجعة الجداول الحالية (contacts, contact_facts, contact_stances, contact_messages) وتحديد الحقول الناقصة للإضافة في P2.

المخرجات

  • قائمة المصادر المتاحة + تنسيقاتها
  • قرار استراتيجية RAGFlow (Dataset-per-contact)
  • تحديد الـ 2 pilots
⬇️ يعتمد على: م input من هدرا (المصادر). يليه: Phase 1.

✅ نقطة توقف (Checkpoint): موافقة هدرا على المصادر والـ pilots قبل البدء.

Phase 1 — استيراد واستخراج (Importers + XML Parser)

الهدف: نقل كل الرسائل + بيانات الـ XML إلى Nexus بشكل مهيكل ونظيف.

١.١ WhatsApp Importer

1
بناء service يسحب رسائل جهة الاتصال من WAHA API (/api/contacts/{session}/.../messages) أو يقرأ ملف export.
2
تطبيع كل رسالة → contact_messages (channel=whatsapp, direction, body, source_timestamp) + فهرسة في message_history_index.
3
ربط الرسائل بـ contact عبر ContactIdentifier::normalize() (الرقم المعتاد عندك).

١.٢ Facebook Messenger Importer

4
parser لـ Messenger export (JSON/HTML) → نفس المسار (channel=fb_messenger).
5
مطابقة الـ fb_id مع جدول contacts.fb_id المضاف حديثاً.

١.٣ Facebook XML Profile Parser

6
service يحلل XML الـ profile (friends, education, work, family_members, birthday) ويحوله إلى contact_facts بـ source=fb_xml + confidence مناسب.
7
تحديث contacts: name, company, title, avatar_url من الـ XML.

١.٤ التنظيف

8
تشغيل NormalizeContactImportBatchJob لإزالة التكرار (content hash + timestamp) — موجود عندنا ✅.

المخرجات

  • contact_messages + message_history_index ممتلئة بالرسائل
  • contact_facts من XML لكل جهة
  • تقرير استيراد (عدد الرسائل/الجهات/المكرر)
⬇️ يعتمد على: P0 (المصادر). يليه: P2.

✅ Checkpoint: فحص يدوي لهدرا على الـ 2 pilots إن الرسائل ظهرت صح من غير تشويه.

Phase 2 — التحليل الذكي والبناء المهيكل

الهدف: تحويل الرسائل الخام إلى معرفة مهيكلة (شخصية، مواقف، ثقة، DNA نفسي).

٢.١ تحليل الرسائل (توسيع الموجود)

1
توسيع AnalyzeContactMessagesJob ليشمل كل الرسائل (مش بس ١٠٠) — تقسيم لـ batches عبر UniversalAiGatewayService.
2
استخراج: topics + persona + emotional_baseline + autopilot_rules → contact_analysis_findings.
3
توليد contact_topics + contact_topic_mentions لكل موضوع متكرر.

٢.٢ مواقف هدرا (Stances)

4
توليد contact_stances أوتوماتيك: لكل topic (money, family, business, general) → hedra_stance + boundary_rules + past_incidents (من تحليل الرسائل + ملاحظات هدرا).

٢.٣ الثقة والمخاطر + DNA النفسي (إضافات جديدة)

5
إضافة أعمدة/جداول:
  • contacts.trust_score (0-100) + contacts.red_flags (JSON array)
  • contacts.psychological_dna (JSON): decision_style, triggers, ego_sensitivity, talk_listen_ratio, commitment_reliability
  • contacts.alerts (JSON): تنبيهات هدرا (مثال: "لا تتحدث عن العائلة")
6
حساب القيم من التحليل + قواعد مبدئية (مثال: مارلين → trust_score=0, red_flags=[manipulation, lying], alerts=[no_sharing]).

٢.٤ الحقائق

7
تلخيص الحقائق المستخرجة في contact_facts (category: bio/work/habit/relationship/preference/psychology) بـ confidence متدرج.

المخرجات

  • بروفايل مهيكل: facts + stances + topics + trust + dna + alerts
  • جاهزية للاستهلاك بواسطة الـ Agent
⬇️ يعتمد على: P1 (الرسائل). يليه: P3.

✅ Checkpoint: مراجعة هدرا لبروفايل الـ pilot الموثوق — هل المواقف والثقة منطقية؟

Phase 3 — مزامنة RAGFlow (Chunks + Memories)

الهدف: تخزين كل الرسائل في RAGFlow للاسترجاع الدلالي + سياق الـ Agent.

٣.١ إنشاء Dataset لكل contact

1
POST /datasets → اسم contact_{contact_id}_{slug}، chunk_method=naive.
2
POST /datasets/{id}/documents?type=empty → مستند يحمل الـ chunks.

٣.٢ رفع الرسائل كـ Chunks

3
لكل رسالة (أو مجموعة متقاربة زمنياً): POST /datasets/{id}/documents/{doc}/chunks بـ:
  • content = نص الرسالة + سياق (مين قال إيه)
  • important_keywords = المواضيع
  • tag_kwd = [contact_id, platform, direction]
4
تخزين ragflow_dataset_id + ragflow_doc_id في contacts.metadata للربط العكسي.

٣.٣ Memory للخلاصة (مهم)

5
POST /memories بنوع ["raw","semantic","episodic"] — ونحفظ فيه الخلاصة الذكية فقط (من P2: persona + topics + stances + life events) مش الرسائل الخام.
6
ربط الـ agent: عند الحوار، GET /messages/search جوه الـ Memory ده لاسترجاع السياق.
⚠️ تحذير: متحطش كل الرسائل كـ Memory raw — الـ memory_size افتراضي ٥MB (≈٥٠٠ رسالة). الـ Dataset/chunks هو مخزن الرسائل الكامل؛ الـ Memory للخلاصة بس.

٣.٤ المزامنة الحية (Horizon Job)

7
بناء SyncContactToRagflowJob (queue: peopleconnect) يسمع أي رسالة جديدة (من WAHA webhook) ويرسلها لـ RAGFlow (chunk + تحديث memory).
8
بناء RagflowRetrievalService يغلّف POST /retrieval بـ metadata_condition على contact_id + platform.

المخرجات

  • كل رسائل الـ pilots في RAGFlow (مسترجعة دلالياً)
  • Memory خلاصة لكل جهة
  • مزامنة حية أوتوماتيك
⬇️ يعتمد على: P1+P2. يليه: P4.

✅ Checkpoint: اختبار retrieval حقيقي — اسأل سؤال عن الـ pilot وتأكد إن الـ chunk رجع صح من RAGFlow.

Phase 4 — واجهة الـ Agent + التنبيهات + اللوحة البصرية

الهدف: تحويل كل اللي فوق لـ "بروتوكول جاهز" يتواصل بيه الـ agent + لوحة هدرا البصرية.

٤.١ Agent Handoff Protocol (المخرج الأهم)

1
Generator بيولّد ملف تعليمات لكل contact من (persona + stances + trust + alerts + comm_pref): 
عند الرد على [الاسم]:
├─ النبرة: [دافئة/رسمية/مختصرة]
├─ القناة المفضلة: [واتساب/فيسبوك]
├─ تجنب: [موضوع X — حدود هدرا]
├─ مستوى الثقة: [متوسط] → لا تشارك [بيانات حساسة]
└─ التنبيهات: [لا تتحدث عن العائلة / متلاعب]
2
تخزين البروتوكول في contacts.metadata.handoff_protocol + عرضه للـ agent قبل أي رد.

٤.٢ التنبيهات

3
contacts.alerts (JSON) تظهر للـ agent كـ hard-stop قبل الإرسال + للوحة البصرية كـ badges حمراء.

٤.٣ Visual Profile Board (لوحتك البصرية)

4
صفحة HTML لكل contact (مثل الملف اللي فات) فيها: دائرة ثقة ملونة + خط زمني + بطاقات حقائق + المواقف + التنبيهات + زر "عايز أتواصل دلوقتي" (يطلع البروتوكول جاهز).
5
نشر على n.soulyeg.online/contact_{id}.html (نفس ستايل الملفات اللي عاملينها).

٤.٤ ربط الـ Agent

6
في كل رسالة واردة: الـ agent يحمّل البروتوكول + يعمل retrieval من RAGFlow + يولّد الرد بالنبرة الصحيحة + يفحص الـ boundary_rules قبل الإرسال.

المخرجات

  • نظام تواصل ذكي end-to-end
  • لوحة بصرية لهدرا لكل جهة
  • حماية أوتوماتيك عبر التنبيهات + الثقة
⬇️ يعتمد على: P1+P2+P3. يليه: تشغيل كامل.

✅ Checkpoint نهائي: هدرا يختبر الرد على الـ pilot الموثوق + السامي ويتأكد إن النبرة/الحدود صح.
