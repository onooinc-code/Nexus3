١. واقع ContactHub الحالي في Nexus (من الكود الحي)

✅ البنية التحتية للبيانات المهيكلة (Relational) جاهزة تقريباً بالكامل — فيه جداول مبنية أصلاً لتغطي معظم طلبك. الناقص الفعلي هو: الربط بـ RAGFlow + Pipelines الاستخراج + الـ Agent-facing view.

📊 الجداول الموجودة فعلاً (ميجريشنز حية)

contacts (الأساسي)

name, phone, email, type, title, company, fb_id, relationship_type, priority_level, summary, metadata, attributes

contact_facts جديد اليوم

category(bio/work/habit/relationship), fact_key, fact_value, confidence, source, source_ref

contact_stances جديد اليوم

topic, hedra_stance, boundary_rules, past_incidents ← مواقف ومبادئ هدرا

contact_messages + threads

كل رسائل WA/FB مع channel + direction + timestamp

message_history_index

فهرس موحد cross-platform (whatsapp/fb_messenger/sms) عالي الأداء

contact_analysis_findings

topics, persona, emotional_baseline, autopilot_rules

contact_memories

محتوى مـ Vectorized (يحتاج ربط بـ RAGFlow)

contact_notes

ملاحظات هدرا (note, summary, is_pinned)

contact_reply_rules + rules

قواعد الرد الآلية

contact_topics + mentions

المواضيع المستخرجة من الرسائل

contact_relationships

شبكة العلاقات (source/target/type/strength)

dialogue_tasks

مهام حوارية موجهة بأهداف + checkpoints

contact_profile_snapshots

snapshot كامل للبروفايل (للـ versioning)

contact_audit_events

لوج كل التغييرات (أمان)

contact_custom_fields / tags / aliases

حقول مخصصة + وسوم + أسماء بديلة

🔴 الفجوات الحقيقية (اللي محتاجة بناء)

  • RAGFlow Integration layer: مفيش كود بيربط contact_messages بـ RAGFlow datasets/chunks/memories لسه.
  • XML Parser: مفيش service يحلل ملف Facebook XML profile ويحوله لـ contact_facts.
  • Import Pipelines: مفيش connector جاهز لرسائل WAHA القديمة + Facebook Messenger export.
  • Agent-facing Profile View: مفيش الـ "بروتوكول جاهز" اللي الـ agent يقراه قبل الرد.
  • Trust/Risk + Psychological DNA + Predictive: مفيش جداول مخصصة (هنضيفها).

🧱 مكونات البروفايل (٩ طبقات)

١. الهوية

name, phone, email, fb_id, avatar, company, title, aliases

٢. الحقائق

bio, age, education, workplace, family, habits, preferences

٣. الشخصية

persona, communication_style, emotional_baseline

٤. المواقف والمبادئ

topic → hedra_stance + boundary_rules + past_incidents

٥. المواضيع

٦. الرسائل الكاملة

RAGFlow chunks + contact_messages (WA/FB)

٧. ملاحظات هدرا + تنبيهات

contact_notes + alerts JSON (مثال: "لا تتحدث عن المال")

٨. شبكة العلاقات

contact_relationships + قوة العلاقة

٩. قواعد الرد الآلية

contact_reply_rules + Agent Handoff Protocol

٣. المحاور العشرة المقترحة (أوسع من التخزين)

ده رأي سولي الموسع — مش بس "استخراج وتخزين"، ده هندسة ذكاء تخلي الـ agent يتواصل بأفضل شكل ممكن.

١ Psychological DNA

Decision style, Triggers, Ego sensitivity, Talk/Listen ratio, Commitment reliability — يتخزن في contact_facts (category=psychology)

٢ Trust & Risk Engine

trust_score (0-100) + red_flags[] + interaction_ceiling. مثال: مارلين = hostile/no-trust أوتوماتيك

٣ Communication Preference

best_time, channel_pref (WA/FB), tone (رسمي/دريفت), length, emoji/formal — يتعلم من الرسائل

٤ Predictive Needs

تنبؤ بالاحتياج قبل السؤال + تنبيه لهدرا "فلان غالباً هيبعت بخصوص X"

٥ Relationship Timeline

أول تواصل، محطات، أزمات، انجازات، life events (مواليد/زواج/شغل)

٦ Agent Handoff Protocol

ملف تعليمات مولّد أوتوماتيك: نبرة، محاذير، تركيز، سقف الثقة

٧ Conflict & De-escalation

سيناريوهات + ردود جاهزة للتلاعب/الضغط العصبي + كلمات مفتاحية توقف المحادثة

٨ Dynamic Enrichment

إثراء أوتوماتيك من مصادر عامة (LinkedIn public, بحث) → fact بـ confidence منخفض

٩ Temporal Versioning

كل تحليل = snapshot (contact_profile_snapshots) — الـ agent يقرأ الأحدث + مقارنة التطور

١٠ Visual Profile Board

صفحة HTML ملونة: دائرة ثقة + خط زمني + بطاقات + زر "عايز أتواصل دلوقتي"

💡 المحورين الأهم للتواصل الذكي: رقم ٦ (Agent Handoff Protocol) هو قلب الموضوع، ورقم ٢ (Trust & Risk) بيحميك من الناس السامة زي مارلين.

٤. تكامل RAGFlow — الرأي والتنفيذ المقترح

🔗 طبقتان في RAGFlow لكل contact

الطبقة ١ — Dataset + Chunks (الاسترجاع الدلالي الكامل)

  • كل contact = Dataset اسمه contact_{contact_id}_{slug}
  • كل رسالة (أو مجموعة متقاربة) = chunk واحد بـ metadata: {contact_id, platform, direction, timestamp, sentiment, topics[]}
  • الاسترجاع: POST /retrieval بـ metadata_condition على contact_id + platform

الطبقة ٢ — Memory (لسياق الـ Agent)

  • كل contact = Memory بنوع raw + semantic + episodic
  • الـ agent يعمل GET /messages/search جوه الـ Memory لاسترجاع السياق
⚠️ تحذير سولي: متضيفش كل الرسائل كـ Memory raw — الـ memory_size افتراضي ٥MB (≈٥٠٠ رسالة بس). الأفضل: Chunks في Dataset = مخزن الرسائل الكامل، وMemory = الخلاصة الذكية المستخرجة بس.

📋 جداول RAGFlow المستخدمة

Endpointالاستخدام
POST /datasetsإنشاء Dataset لكل contact
POST /datasets/{id}/documents (type=empty)إنشاء مستند فارغ يحمل chunks
POST /datasets/{id}/documents/{doc}/chunksإضافة chunk لكل رسالة/مجموعة
POST /retrievalاسترجاع دلالي بـ metadata_condition
POST /memoriesإنشاء Memory للخلاصة
POST /messages + GET /messages/searchحفظ وبحث سياق الـ agent

٥. بروتوكول الـ Agent (كيف يتواصل بأفضل شكل)

📜 هيكل ملف الـ Handoff Protocol (يُولّد أوتوماتيك)

عند الرد على [اسم جهة الاتصال]:
├─ النبرة: [دافئة / رسمية / مختصرة / محايدة]
├─ القناة المفضلة: [واتساب / فيسبوك]
├─ أوقات الاستجابة الأفضل: [من الساعة X للساعة Y]
├─ تجنب تماماً: [الموضوع A — حدود هدرا]
├─ ركّز على: [اهتماماته المعروفة]
├─ لو سأل عن [المال]: رد بـ [قاعدة هدرا X]
├─ مستوى الثقة: [متوسط] → لا تشارك [بيانات حساسة]
├─ التنبيهات: [لا تتحدث عن العائلة / شخص متلاعب]
└─ في حالة الضغط العصبي: [تأخير الرد + نبرة محايدة]

٦. الخطة التنفيذية المقترحة (مراحل — للاعتماد)

Phase 0 — التحضير (مخطط)
  • تحديد مصادر الرسائل المتاحة فعلاً (WAHA export؟ Facebook export؟ XML files؟)
  • تجهيز بيئة RAGFlow (API key موجود عندنا ✅)
  • تحديد أول جهة اتصال تجريبية (مثلاً واحدة موثوقة + واحدة سامة لاختبار الـ boundary)
Phase 1 — الاستيراد والاستخراج
  • بناء WA Importer + FB Importer + XML Profile Parser
  • تحويل الرسائل → contact_messages + message_history_index
  • تحويل XML → contact_facts (source=fb_xml)
Phase 2 — التحليل الذكي
  • تشغيل AI Analysis → contact_analysis_findings (topics, persona, sentiment)
  • توليد contact_stances (مواقف هدرا) أوتوماتيك من الرسائل
  • حساب trust_score + red_flags + psychological_dna
Phase 3 — مزامنة RAGFlow
  • إنشاء Dataset لكل contact + chunks للرسائل بـ metadata
  • إنشاء Memory + حفظ الخلاصة الذكية (semantic/episodic)
  • Horizon job يسمع الرسائل الجديدة ويرسلها لـ RAGFlow أوتوماتيك
Phase 4 — الـ Agent View + التنبيهات
  • توليد Agent Handoff Protocol لكل contact
  • إضافة alerts JSON في البروفايل (تنبيهات هدرا)
  • بناء Visual Profile Board (HTML ملون زي اللي بتشوفه دلوقتي)
🎯 نقطة البداية المقترحة: نبدأ بـ Phase 1 على مصدر واحد تجريبي (مثلاً رسائل واتساب جهة واحدة) عشان نتأكد إن المسار شغال ١٠٠٪ قبل التعميم.
